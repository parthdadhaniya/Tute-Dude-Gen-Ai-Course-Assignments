Retrieval-Augmented Generation (RAG) is an architectural pattern in artificial intelligence that combines the generative capabilities of large language models with the precision of external information retrieval systems. In a standard language model setup, the model relies exclusively on the parametric weights learned during its pre-training phase. While powerful, this approach has notable drawbacks: training data becomes stale over time, domain-specific proprietary information is inaccessible, and models frequently hallucinate plausible-sounding falsehoods when asked about obscure or evolving topics.

RAG resolves these limitations by fetching relevant documents from an external corpus at inference time. The workflow begins during data ingestion: documents are collected, broken down into smaller semantic chunks, and transformed into high-dimensional numerical vectors using an embedding model. These embeddings are stored in specialized vector stores such as ChromaDB or FAISS. When a user asks a question, the system converts the query into the same vector space, finds the most relevant document chunks through similarity search algorithms, and supplies those chunks as grounding context to the LLM.

Vector stores play a crucial role in modern GenAI architectures. ChromaDB is an open-source, embedded vector database designed to be developer-friendly, running locally with zero external server dependencies while offering persistent storage and metadata filtering. FAISS, developed by Meta AI, is optimized for extremely fast similarity search across millions of vectors using index structures like Flat, IVFFlat, and HNSW.

Advanced retrieval strategies enhance the standard similarity search pipeline. Maximal Marginal Relevance (MMR) balances relevance to the user query with the novelty and diversity among the retrieved documents. This prevents returning three or four nearly identical chunks of text. Multi-Query Retriever uses an LLM to generate alternative phrasing of the user's initial question from different angles, retrieving documents for each query variation and merging the results. Contextual Compression uses small extraction models to strip out irrelevant filler sentences from retrieved documents before passing them to the final LLM, reducing token consumption and minimizing distraction.

Large Language Models like GPT-4, GPT-3.5-Turbo, and Claude rely on token-based autoregressive generation. In conversational RAG systems, conversation history must be preserved and summarized so follow-up queries like "How does it compare to the second one?" can be resolved into standalone retrieval queries before searching the vector database.
